# Canary — islam.museum release notes

The museum's public release notes: every change that lands on `main`, recorded in
reader's language in the same commit that makes the change. Newest release first.
The site build reads the version and date from the top block below and shows them
in the footer of every page and on the changelog page (`/{lang}/changelog/`).

Rules for every agent and contributor (`docs/engineering/15-release-notes-and-versioning.md`):
append your entry under the current version block, grouped by kind — Added, Changed,
Fixed, Removed, Performance, Tests, Data, Breaking, Rolled back. Write what changed
and why it matters, never a bare commit message. If your change bumps the version,
open a new block on top with the new version and today's date.

---

## v2.24.0 — 2026-11-18
### Added
- **Spanish (`es`) as the fifth language of the museum — infrastructure and interface (branch `release/spanish`, proposal `docs/delegation/spanish-language-proposal.md`).** The site now builds `/es/` beside `/ar/`, `/en/`, `/ur/` and `/fr/`: the language switcher cycles ar → en → ur → fr → es, each page carries a Spanish hreflang alternate, a `pagefind-es` search index is built, and the site Worker, the R2 publish list and the deploy workflow know the new folders. `i18n/es.yaml` carries the interface in Spanish, translated from `i18n/en.yaml` by AI agents and not yet read by a human; dates, eras and month names have Spanish forms. What a visitor does **not** get yet: no record has Spanish prose, labels or summaries, and the education, kids and tour datasets have no Spanish fields, so those show English (then Arabic) inside the Spanish frame; passage pages have no Spanish translation of the Qur'an (no source is chosen). Spanish stays outside the parity requirements (`PUBLISHED_LANGS`) until its corpus lands, and no language count in `docs/status.md`, the site copy or the outreach files is changed. The `spanish` lane (`docs/agents/lanes/spanish.md`, queue `scripts/es-queue.ts`, progress `docs/delegation/spanish-progress.md`) carries the corpus work, in parallel with the French lane. The language rule in `AGENTS.md` and `docs/language.md` now names Spanish for new content. Nothing is live: `release/spanish` is not merged to `main` and nothing is deployed.
### Added
- **The museum opens in the visitor's own language.** Someone who arrives at the bare address `islam.museum/` is now taken to the museum in their browser's default language when that language is English, Urdu, French or Spanish; Arabic speakers, speakers of any other language, and browsers without JavaScript get the Arabic page the root has always served. Only the root does this: `/ar/`, `/en/` and every deeper address stay where they are, so choosing a language in the header is never undone. A language chosen in the header is remembered: the next visit to the root opens in that language, whatever the browser's own language, until the visitor chooses another. The only thing kept is that language code, in the visitor's own browser storage, never sent anywhere (the privacy page lists it); search-engine crawlers are left on the Arabic root. The change lives in one shared script file (`site/public/shell/shell.js`), so no page is rewritten.

### Changed
- **Translation now runs on a local model on the founder's Mac (from wave 11).** Spanish and French prose are translated from English by TranslateGemma 27B, served locally with Ollama, under `scripts/local-mt/` (a translator that protects citations, link ids and markers and checks every record against its English source, and a supervisor that restarts it). Claude manages the queue, the checks and the merges and no longer writes the translations. The local drafts are freer than the earlier ones and are labelled with the model's name on every record; nobody has read them.
### Data
- **First Spanish prose: 5,033 records (`content/es/`, branch `release/spanish`).** Every eligible record of the canon's top two tiers and 792 object and building records, outside the sacred classes — people such as Umm Salama, al-Nawawi, al-Tabari, Rumi and Mansa Musa, places such as Granada, Qayrawan, Bukhara and Delhi, buildings such as the Dome of the Rock and al-Azhar, events, works, concepts and periods — now have their full prose in Spanish, translated from the English by AI agents and checked mechanically against it (same links, citations, headings and paragraphs; no typed honorific). No human has read them. About 33,400 prose files are still English under `/es/`, and every label and summary, and the education, kids and tour datasets are still not in Spanish.

### Fixed
- **French pages no longer stop the site build.** The table of other prophets' names had no French entry, so a French page that mentioned the Prophet made the build fail (`/fr/event/hijra/`). The French and Spanish tables are both present now.
- **Spanish prose reads left to right and keeps its section roles.** The entity page, the place map and several components treated every language but English as right-to-left (fix taken unchanged from the French lane), and the Spanish headings of the Brief, young-visitors, scholars and reading-level sections are registered. The validator's "Sunni entry first" rule recognises the Spanish label.
- **Pages that read the education, kids, tour and card datasets no longer break in French and Spanish.** Those datasets exist in Arabic, English and Urdu only; a page such as `/fr/shabab/detective/` read a French field that was not there and stopped the build. The loaders now fill a missing French or Spanish field from English, then Arabic, when the data is read, so the page shows the English text until the translation lands.
- **The Time Browser has its data in French and Spanish.** Its generator wrote the per-language files for Arabic, English and Urdu only, which stopped the build at the Time Browser's stop pages.
- **The kids' reader is built only where its text exists.** A record flagged for the kids' reader got a reader page, and links to it, in every language that had any prose for it; in French that page had no Explorers text and stopped the build, and in Spanish the links led nowhere. The page and its links now exist only where the record's prose in that language has the Explorers section.

### Tests
- **The site check reads a partly translated strings file.** `scripts/check-site.ts` crashed on a language whose `i18n` file lacks a section (French today); it now falls back to the English string, as the pages do.
- **The Qur'an passage files are back to their frozen content (branch `release/spanish`).** A corpus-wide change on `main` (commit `7d509c17a5`) had inserted direction marks around parentheses in 3,528 of the 6,394 Qur'an passage files: in the Urdu translation text (3,522 values) and in relation notes (21). The Arabic Qur'an text, the search text and the English translation were not touched. On the founder's instruction the 3,528 files are restored to what they were before that commit, and the validator no longer applies the parenthesis rule to the frozen passage files. Until the page renderer isolates them, parentheses in the Urdu translation on passage pages may be drawn the wrong way round.
- **The accessible books step runs in five languages.** `scripts/a11y-books.ts` kept one list per language for four of the five and crashed on Spanish at the very end of the first full build of `release/spanish` (after 460,598 pages had been built and checked with 0 errors). French and Spanish now also go through their own braille tables instead of the Arabic path. Known limit: the Spanish and French braille files lose accented letters.
- **Three tests assert the published languages again.** `pipeline.test.ts`, `tour.test.ts` and `modern.test.ts` expected French prose, French tour fields and a four-language fixture that do not exist yet, which failed the build workflow on the release branches. All 634 tests pass.

- **The after-build site check reads a partly translated language the way its pages do.** `scripts/check-site.ts` now takes its strings through the site's own loader, which fills a key French has not translated yet from English, so the check compares each page with the text it really shows instead of crashing on the missing French section. The embed index and not-found page checks are unchanged for Arabic, English and Urdu.

- **French release verification:** missing French dataset fields now have safe tour, gallery and world-page fallbacks, French prophet-name guards keep honorific rendering scoped correctly, and localized component types accept optional French fields during the rollout. The French queue imports the existing repository path helper correctly. Validate now builds the graph cache before its unit tests; regression tests cover French routes, search-index routing and the R2 sync prefix configuration.
- **A web address in Arabic or Urdu text no longer swallows the punctuation after it.** A bare address typed in a summary or article (`www.example.org` or `https://…`) now ends before «؛», «،», «؟» and «۔», the way it already ended before a Latin full stop, comma or semicolon. Before this, «…والموقع www.semerkand.tv؛» made the semicolon part of the link, so the link on the source page `wikipedia-semerkand-tv-diq` was broken and the full-site link check on `main` failed; the IslamQA listing page had the same fault with «،». Bracketed links are unchanged.
- **Arabic and Urdu parentheses now display the right way round.** About 20,400 files had plain brackets around Arabic-script text, which right-to-left pages draw turned the wrong way, such as «الخطيب (المؤلف)»: 247 Arabic and 7,052 Urdu articles, the Arabic and Urdu UI strings and about 13,100 data records. They now carry the U+2066/U+2069 isolates the rule requires, and `npm run validate` rejects a plain one in new Arabic or Urdu content. The Arabic and Urdu “approximately” date tag and the names in the art and Muslim-world data files of the site got the same fix.
- **ﷺ now appears only for Prophet Muhammad, in Arabic, English and Urdu.** The page renderer used to add it to the first «النبي» / "the Prophet" / «رسول اللہ» of every article, so «معركة النبي صموئيل», "the Prophet Daniel", «عيسى رسول الله» and a bare «النبي» on another prophet's own page carried Muhammad's mark (about fifty such marks across the site, found by rendering every article before and after). A title with another prophet named beside it is now left unmarked; the rule for new content is in `AGENTS.md`, and `npm run validate` checks that source texts keep ﷺ only beside Muhammad.
