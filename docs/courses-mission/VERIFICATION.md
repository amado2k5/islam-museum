# Verification ledger: the courses mission

The board, its oracles and its final state, written to be re-checked by someone who trusts none of it. The form is the Grand Tour run's (`docs/fable-run/VERIFICATION.md`).

## How to read it

Three states are kept apart everywhere:

| State | Commit | What it is |
|---|---|---|
| Production | `8d1b0ef9d7556cc570e9e452e8cd3257e346ab1f` | What visitors see: build run 42832259141, site v1.10.0, deployed 2026-11-10T18:33:45Z. Read from `/api/v1/meta/deploy.json` by the audit oracle. |
| Baseline | `800467e93e2c9ef073807f6bd5c7b717b028f859` | `origin/main` when the branch was cut. The "before" of every repository measurement. |
| This mission | the commits named in the board | What the run built. Its first two phases went to `release/uat`, which the founder merged into `main` on 12 November 2026; the finished work was then merged to `main` from the branch `courses/ontario-main`. **None of it is live.** Merged is not deployed; deployment is the founder's. |

A claim about visitors is a claim about production. One oracle measures production (the audit); it says so in its output. Every other number is about the branch.

An **oracle** is a committed file under `scripts/courses/`. Running it prints what it measured and ends with one line, `RESULT: GREEN (...)` or `RESULT: NOT-GREEN (...)`. Each prints the commit it ran at and how many measured files were uncommitted at the time. With `--save` its output is kept under `docs/courses-mission/oracle-output/`.

## How to re-run everything

From the repository root:

```bash
npm ci && npm --prefix site ci                      # once
npm run graph && npm run derive                     # the graph artifact and the derived files, about two minutes
python3 scripts/courses/scoped_build.py             # the courses pages and their neighbours, as a production build
python3 scripts/courses/fetch_ontario.py "SSHG - Grade 4" ontario-sshg-2023-g4     # the authority's document, for statement 6 (network)
```

Then each oracle with the command in its row of the board. `o01` and `fetch_ontario.py` need the network; `o08` runs the validator (about ten minutes); `o11` runs two scoped builds (about two minutes). `python3 scripts/courses/board.py` rewrites the board; `--check` fails if the board differs from the captured outputs.

## Definitions the numbers rest on

Each is a choice; a different choice gives a different number.

- **Interaction.** One tap or click on a control a student can see: a link, or the summary of a closed disclosure. Scrolling is not counted. Measured at 390 × 844.
- **Served.** A lesson is served when its page answers 200 in the build, is a lesson page of the new surface, and has a title.
- **Readable with scripts off.** The title, every step of the loop, every discovery card with its text, the curriculum codes, the check and a way onward are rendered and visible in a browser with JavaScript disabled, and no control that needs a script is shown.
- **Real record.** A file `data/<class>/<slug>.yaml`. A stub (a line in `data/_stubs*.yaml`) is not a record.
- **Already cited (weak).** The source record existed at the baseline commit.
- **Already cited (strict).** The source id appears in the linked record's own data file or prose at the baseline commit. The comparison is by id: a record citing the same work under another id would not match.
- **The authority's text.** What `fetch_ontario.py` extracts from the Ministry's own content service: tags removed, entities decoded, whitespace collapsed, no word changed.
- **Fidelity under the quotation rule.** The repository stores at most 40 words of a source verbatim. A record's expectation text is `quote_official(official text)`: example lists replaced by `[…]`, anything still over 40 words cut and ended with ` …`. "Identical" means byte-identical to that function's output. It is the official wording with marked omissions, not the full wording.
- **Defect, closed, registered.** A defect is one row of a fresh reviewer's table. Closed: changed in the code and then seen gone by a later reviewer on a re-taken screenshot. Registered: left standing with its reason in `vision/defects.json`.
- **Byte-identical.** The same scoped production build run twice over the same data, once with the integration base's site source and once with the branch's; `filecmp` on the HTML.
- **Integration base.** For the first two phases, `release/uat` with phase 1 merged (`841cdc52c4`). For the final branch, the commit of `main` it last merged (`git merge-base HEAD origin/main`), which already held those two phases. An oracle's row names the commit it ran at; rows that ran on a phase branch were not re-run on the final branch unless the row's commit says so.

## What is not green, and why

- **Statements 4 and 5.** Green for every course made by the pipeline; not green for the original pilot, where 3 of 15 connections point at stubs. The pilot was measured and left for the founder.
- **Statement 8.** The validator does not print `0 errors`. Of 69 errors on the merged branch, 26 were this work's (un-isolated Arabic-script parentheses in course summaries) and were corrected in the following commit, after which the validator was not re-run to completion; 43 are in records outside this work, and `main` failed this gate at the baseline too. Cite-check prints `0 fail` over all 643 course records.
- **Statement 11**, as first written, said Urdu was untouched. The user widened the boundary (Urdu; a homepage section; an explorer card) and the oracle checks the widened boundary.
- **Not run on the final branch:** the full site build, and CI, on the user's instruction not to wait for them; `o03` and `o10` (taps, no-script) and the vision pass, whose rows are from the Arabic and English surface before Urdu was added.

Everything else this work does not do is listed in `PUBLISH.md`.
