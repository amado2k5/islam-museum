# Lane `prose-backfill`: Arabic prose for the records that have none, and depth for the thin ones

**Scope.** The gap left by the data-first lanes (Wikidata import waves 1–3, automated harvests): ~13,500 entities have a `data/` record but no `content/ar/` prose, and ~6,500 more have an Arabic prose file under 800 bytes (bibliography cards, captions, reader frames — `source/*`, `media/*`, `listing/*`, `dataset/*`, `language/*`, `passage/quran-*` — are excluded; they do not take prose pages). The ranked work list is `docs/delegation/empty-records-priority.md`, regenerated 21 Oct 2026; re-run the ranking after each large merge so finished entities drop out.

**Work order.** The report sorts every gap by inbound links — how many data and prose files already point at the entity. A page readers reach often is written first; the ~13,300 zero-link entities (mostly the Wikidata-import tail: Ottoman türbes, Anatolian mesjids, Yemeni madrasas, hadith narrators) rank last and are worked class by class in slug order. Within a class, the thin files (a one-line `موجز`) come before zero-link missing files: a short page a reader can already reach beats a long tail nobody sees.

**What each entity gets.** A `content/ar/<class>/<slug>.md` file written from the sources already cited in the data record — never from Wikidata or Wikipedia alone, they are pointers (`docs/agents/content-standards.md`, `docs/sources-policy.md`). Where the data record cites only `source/wikidata`, find a real source in the library (`scripts/harvest/library/books.yaml`, the mining lanes' scanned books) or leave the entity and record the miss in the progress file; no page without a citation. Follow the class's existing shape: `## موجز` lead, then the sections the class uses (see `content/ar/event/expedition-of-al-sawiq.md` for events). No honorifics, no Qur'an text, no verdicts; contested topics get `perspectives` in the data record, not in the voice. English and Urdu prose are **not** required in the same commit for this lane — the `en-translation` lane picks up new Arabic pages; note each batch so its progress file stays accurate.

**Thin-file rule.** Enrichment means new cited content, not padding: add what the cited sources support (a second section, the missing dated facts with a second source, the relations the prose names). If the sources support nothing more, leave the file and log it.

**Batches.** At most 25 entities per commit, grouped by class and by source so one book is mined once. After each batch: `npm run validate` (0 errors), `npm test`, `npm run coverage` in the same commit, explicit paths only, attribution trailers, fetch-merge-push to `main`.

**Branch / stubs / progress.** `content/prose-backfill`; `data/_stubs.d/prose-backfill.yaml` (append-only, for targets prose mentions that have no record); `docs/delegation/prose-backfill-progress.md` — one line per batch: files written, entities skipped-no-source, next position in the report. Commit prefix `content(prose-backfill)`.
