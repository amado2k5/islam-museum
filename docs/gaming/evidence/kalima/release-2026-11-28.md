# Kalima: release evidence, 28 November 2026

**Decision.** The founder, in chat on 28 November 2026, asked for one game to be chosen and finished, and then to "make it as completed and not prototype once it is done". Kalima was chosen because it has no art, no 3D and no historical figure, and everything it shows comes from museum records. Its status is `production` in [`release-status.json`](../../spec-production/release-status.json) and `released` in `gaming/games/registry.json`, on his word.

**What was not done, and still is not.** The games' specification (`spec-v2/16-QUALITY-AND-PLAYTESTING.md`) asks for these before a *validated* release. The founder released Kalima without them:
- **A playtest.** No person outside the agents has played it, and no independent reviewer has played it without being told the answer.
- **Native readers.** No native speaker has read the strings or word lists in Urdu, French, Spanish, Turkish or Indonesian. They are machine work.
- **Real phones.** No real phone has been used: the phone checks are an emulated 375×812 screen in desktop Chrome.

These remain open, and are the next things to do for Kalima.

## Changed for this release

1. **A lighter first visit.** The game now loads a names file holding only its own words: 17 to 53 KB a language, where it loaded the whole label file of 0.4 to 0.8 MB. The pack builder writes the file (`word-labels.v1.<lang>.json`), and a test holds it equal to the label file for those words.
2. **Contrast.** Three colour pairs were below WCAG 2.2 AA:
   - in dark mode, the letter on a "right" tile (3.47:1) and on a "near" tile (2.96:1);
   - in light mode, a ruled-out key faded to 60% (2.53:1).

   Dark-mode marks now carry dark letters, and a ruled-out key is struck through instead of faded. The lowest letter contrast on any marked tile or key is now 5.35:1.

   The stylesheet is shared, so the other three daily games get the same fix.
3. **The label.** The prototype label is gone from Kalima's page, and from its card on the museum's games page. That page's introduction now says that Kalima is finished and the others are prototypes, in all seven languages.

## Checks run

All checks ran on this machine against the local host (`tools/local-host.ts` over `dist/release`). None ran against UAT or production.

- **`tools/kalima-play.ts` (new):** 56 runs, no problem found ([`kalima-play-2026-11-28.json`](kalima-play-2026-11-28.json)).
  - **Coverage:** whole games with the keyboard alone, in 7 languages × phone (375×812, touch) and desktop (1440×900) × light and dark × one game won and one lost, on the puzzle of 1 December 2026.
  - **Each run checks:**
    - the page's direction;
    - the end card, and its link to the museum's record;
    - that the finished day is kept after a reload;
    - no console error;
    - every marked tile and key at 4.5:1 or more.
  - **Captures:** Arabic and English on a phone, light and dark, are kept here.
  - **How the keys are sent:** for letters outside a US keyboard (Arabic, Urdu, some Turkish), the test sends the key event a keyboard in that language sends. The test browser cannot press those keys itself.
- **`tools/daily-check.ts`:** all four daily games in 7 languages, on a phone and a desktop, one move each. 56 runs, no problem.
- **Unit tests:** `npm --prefix gaming test` covers the day's word for 400 days in every language. Each day's word is the same for everyone, can be solved, and names a museum record with a source.

## What a person should check next

1. **A playtest:** play a week of days on a real phone, in Arabic and in English.
2. **Native readers:** have native speakers read the Urdu, Turkish and Indonesian word lists and strings.
3. **Assistive tools:** run a screen reader (VoiceOver on iPhone, TalkBack on Android) through one whole game.
