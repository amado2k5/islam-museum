# Product vision and scope
A premium independent historical gaming destination, not an educational worksheet. Audience: players who like strategy, craft, discovery and puzzles, including people with no prior knowledge of history. Historical richness should enable decisions and surprising connections, not create reading prerequisites. Each game earns attention on its own. Canonical PC experience prioritizes quality; directory-friendly and mobile puzzle editions are separate deliverables only when suitable.

## Product architecture
PLAY is a storefront and launcher; WORLDS is immersive exploration inside appropriate games; CREATE is local creator tooling; SDK is public contracts; COMMUNITY is curated or local-first sharing, never a fake live feed; STUDIO is internal profiling and QA. These are navigation concepts, not six new mandatory sites. Keep UI cohesive at platform level; games retain distinct art direction. Portal first screen: featured real scene, continue game, today's challenges, genre library, new releases, creator entry. No forced login, no carousel that blocks access, no splash animation that delays interaction. Search/filter by play duration, genre, difficulty, hardware and languages. All cards show actual release status.

## Player experience principles
Core verbs before exposition. Make cause/effect observable. Offer a risk and a reward with alternate viable routes. Teach via doing, contextual prompts, optional reference panels, not long blocking tutorials. Every click should have a visible result; player errors should be recoverable. One primary action per context, readable HUD, tooltips on demand, never cover the interesting scene with chrome. Keep audio optional and settings remembered. Build challenge archives, sandbox, and self-directed goals; difficulty affects decisions, not merely enemy HP or grind. Preserve clean exits and pause. A first minute should deliver a memorable action or discovery; a first week should expose new systems rather than repeated fetch quests.

## Scope and acceptance
M1/M2 establish reference quality before expanding; a small rich district is better than a sparse continent. Ten GDDs specify launch scope, not infinite content. Additional multiplayer, public marketplace, shared persistent economy, voiceovers in every language and full no-code programming are expansion work unless a milestone explicitly approves them. No guarantee of reviews, viral growth or user count; build for delight, measure actual behavior with opt-in privacy. Avoid naming or visual similarity that suggests official association with benchmark games; conduct title/IP search before publication.
