# Shared systems and simulation contracts
Build packages when two consumers justify abstraction; use strict TypeScript ESM and locked package manager. Candidate layout `gaming/apps/portal`, `games/*`, `packages/{runtime,content,render,audio,input,ui,save,replay,i18n,sdk,mod-runtime,portal-adapters}`, `content`, `tools`, `scripts`, `tests`, `docs`. Adapt to actual repo. Avoid a generic engine rewrite. Define lifecycle mount → load → ready → play/pause → save → dispose, cancelable tasks, explicit ownership of GPU/audio/worker resources. Input action mapping for keyboard, mouse, gamepad; support touch for games suited to it. Context menu, focus loss and pointer lock behavior recoverable. Never capture keyboard while typing in fields; escape returns control.

## Simulation
Pure game-specific state reducer with explicit version, seeded PRNG and fixed-step clock. Use integer/fixed-point economics or documented deterministic arithmetic; simulation command log and hashes at checkpoints. Rendering interpolates but never affects score. Async workers run bounded jobs; message version, sequence, cancellation and backpressure. Rigid physics via Rapier where appropriate; purpose-built gear/energy, flow network, ray optics and simplified structural rules for House/Architects; separate visual effects. City and dynasty use aggregate economies and representative crowds. AI chooses only legal actions with visible constraints; difficulty adds strategic sophistication rather than hidden cheating. Simulation labs generate seeded strategies, test invariants (nonnegative resources, conservation where appropriate, no impossible objectives, terminal outcome), detect dominance and log reproducible exploits. Do not force deterministic GPU particles or floating physics across devices; replay via snapshots and validated outcomes if necessary.

## Persistence and sharing
IndexedDB transactions for state plus metadata, OPFS only when justified for larger assets; quota checks, export/import, storage persistence request only where appropriate. Save envelope: game/version, schemaVersion, content digest, mod lock, UTC timestamp, seed, state, checksum and optional replay. Atomic write new save then update pointer; retain prior valid snapshot; test corrupted/missing/versioned records. Separate canonical and modded saves; never silently downgrade or overwrite. Migration chain with fixtures; backup before migration. Local progress never represented as verified global score. Share small seed/version URLs, large bundles as explicit files; no PII or secrets in share links. Replay captures commands, initial state, rules/content version and checkpoints; replay unavailable when incompatible, provide clear explanation. Photo mode disables competitive timing only where rules permit; no score manipulation. Reuse daily generator with UTC date, versioned dataset, seeded selection, uniqueness rules and solver proof, archive accessible. No runtime LLM dependency. Audio and rendering pause when hidden; simulation policy per game explicit; no missed-day penalty.
