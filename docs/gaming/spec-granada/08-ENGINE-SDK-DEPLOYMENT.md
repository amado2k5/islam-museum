### Runtime boundaries
- **Authoritative simulation:** state machine, commands, transactions, quest/diplomacy and deterministic event journal. Runs in worker where appropriate, pure tests outside rendering. No DOM or GPU dependencies.
- **Presentation:** render snapshot/diff, interpolated movement, camera, scene streaming, audio and input; sends typed commands; cannot mint resources or resolve authoritative shipment by animation.
- **Content compiler:** verified game-specific historical pack, scenario fixtures, era-filtered assets, translations and hashes. No runtime LLM or full graph load.
- **Platform adapter:** lifecycle, settings, content lookup, save, mod registry, telemetry policy, share/export and localization. All network access explicitly scoped.

Proposed command contract, subject to actual SDK compatibility:
```ts
// Values are DTOs, not references to mutable simulation state.
type GranadaCommand =
  | {kind:'harvest'; plotId:string; allocation:AllocationDTO}
  | {kind:'placeModule'; blueprint:ModulePlacementDTO}
  | {kind:'marketOrder'; quoteId:string; quantity:number; side:'buy'|'sell'}
  | {kind:'acceptContract'; contractId:string}
  | {kind:'dispatch'; shipmentId:string; routeId:string}
  | {kind:'councilChoice'; eventId:string; optionId:string};
interface GranadaEnvelope {
  schemaVersion:number; commandId:string; sequence:number;
  expectedStateVersion:number; tick:number; command:GranadaCommand;
}
interface GranadaPort {
  preview(cmd:GranadaEnvelope):Promise<PreviewDTO>;
  submit(cmd:GranadaEnvelope):Promise<CommandResultDTO>;
  snapshot(query:SnapshotQueryDTO):Promise<SnapshotDTO>;
  subscribe(listener:(event:StateEventDTO)=>void):()=>void;
}
```
Use discriminated errors (invalid placement, quote expired, insufficient stock, unauthorized capability, conflict, incompatible content); command ID deduplicates retries; stale state version rejected or re-previewed. Worker messages schema-validated, bounded size, no arbitrary callback or host object. Preview side-effect-free. Authoritative commands commit atomically; notifications from journal. Expose typed queries for plot forecasts, inventory by location, market quotes, construction costs, quest state, route estimates, defense readiness and source inspector. Use per-game module namespace and semver. Public APIs only after verified consumers, docs and compatibility tests.

## Saves, recovery and portability
Save envelope: game ID, save format, game version, content/asset digest, mod lock, scenario seed, simulation tick, RNG state, state snapshot, pending transactions, replay journal checkpoint, locale-independent IDs, checksum. IndexedDB for saves and metadata; evaluate OPFS for large local worlds where supported; cache assets separately with bounded storage and quota handling. No mandatory account. Save atomic revision then update slot pointer; retain previous good revision, rotating autosaves; simulate crash between steps, quota exhaustion, corruption, reload while pending shipment/quest, device loss. Migration test from previous version, backup before transform; if incompatible, preserve export and readable error, never silently delete. Local file import schema/version/size validated; modded saves separate. No remote sync until approved. Browser storage can be cleared; make export and backup clear. Offline capability only advertise if tested; first visit requires network to fetch game; no install prompt.

## Extension ecosystem
T1 declarative content: namespaced crops, recipes, price tuning for sandbox, buildings/skins, maps, characters, quests, scenes, scenarios and translation packs. New definitions must validate schema, units, reference IDs, resource bounds, era/provenance, license and digest. No arbitrary JS/HTML/SVG/shader execution. T2 behavior remains disabled until independently audited V2 isolation/quotas/capabilities. T3 independent games linked or sandboxed on separate origin as V2. Mod data can alter fictional rules only in modded profile; cannot overwrite official history or canonical score. Registry import via HTTPS manifest/GitHub release asset with CORS/local ZIP; no cloning/install scripts in browser, no implicit credential transmission. Preview digest, dependencies, permissions, size and compatibility; install explicit, pin versions, disable/recover safe mode, uninstall preserving save warning. Reject ZIP traversal/bombs, dangerous paths, oversized meshes/textures, malformed JSON/glTF, remote resource references, prototype pollution, dependency cycles, scripts and unbounded expressions. Verify publisher rights; digest ensures integrity not trust. Worker alone not security sandbox. Independent adversarial tests per V2.

Example independent pack: `community.example:olive-estate` adds fictional building skin, bounded crop recipe variant and a quest using stable IDs. Demonstrate install from local ZIP and public immutable manifest, visual preview, playable rule effect, save/reload, disable and rollback without core edits. Provide TypeScript definitions, JSON Schema, `init/validate/pack/test` commands adapted to actual SDK, developer guide, sample repo or isolated fixture, debugging and migration. Creator Studio supports building blueprint, region and quest authoring with no-code validated forms and source/licensing metadata. Cross-game interoperability: export fortress blueprint to Architects and import compatible building from Architects, recalculating cost/placement. Validate two round trips overall per V2, no hidden dependency on owning or playing other games.
